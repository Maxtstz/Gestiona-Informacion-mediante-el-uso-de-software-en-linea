# Gestiona-Informacion-mediante-el-uso-de-software-en-linea

Caracteristicas de GitHub
GitHub ofrece herramientas clave como 
-alojamiento de repositorios en la nube,
-control de versiones mediante Git y
-herramientas de colaboración, las cuales sirven opara equipos de desarrollo. 
Facilita la gestión de proyectos de código abierto y permite integrar flujos de 
trabajo automatizados para mejorar la eficiencia en la programación.

Desventajas de GitHub 
Por otro lado, la plataforma conlleva retos significativos como: 
-curva de aprendizaje compleja: para quienes no están familiarizados con la línea de comandos
-riesgo de seguridad por filtración de datos si no se gestionan bien los permisos y 
-dependencia total de una infraestructura ajena. 
Al ser un servicio propietario, los desarrolladores quedan vulnerables ante posibles cambios en los términos de uso o caídas de red que detienen el flujo de trabajo,
sumado a que el soporte técnico avanzado y las funciones de seguridad más robustas suelen estar restringidas a planes de pago con costos elevados para organizaciones de mayor escala.

Diferencias entre

Repository: Es el directorio o espacio de almacenamiento donde se gestiona un proyecto íntegro mediante Git. 
Su función principal es resguardar todos los archivos, carpetas y metadatos, manteniendo un registro detallado de cada modificación en una base de datos interna. 
Esto permite reconstruir cualquier versión previa del proyecto y gestionar el acceso de distintos colaboradores a la información.


Commit: Es una operación que registra de forma permanente los cambios realizados en los archivos dentro del historial del repositorio. 
Al ejecutar un commit, el sistema genera un identificador único y guarda el estado exacto del código en ese instante junto con un mensaje explicativo. 
Funciona como un punto de restauración que garantiza la integridad de la evolución del software a lo largo del tiempo.


Branch: Es una via alternativa del flujo de trabajo principal que permite desarrollar tareas de forma aislada al otro archivo. 
Cuando creas  una rama, se genera un entorno independiente donde se pueden modificar archivos sin alterar la versión estable del proyecto inicial. 
Una vez que las modificaciones han sido probadas y validadas, se integran nuevamente a la línea de desarrollo principal mediante un proceso de fusión.


Pull request: Es un mecanismo de comunicación que solicita la integración de cambios desde una rama o un fork hacia el repositorio de destino. 
Su propósito es facilitar la revisión de código, permitiendo que los administradores del proyecto examinen las modificaciones, discutan posibles ajustes y 
realicen pruebas de compatibilidad antes de que el nuevo código sea incorporado definitivamente a la rama principal.


Fork:Es una copia exacta de un repositorio que se aloja en la cuenta de un usuario distinto al propietario original. 
Esta función permite que un desarrollador trabaje sobre un proyecto ajeno sin necesidad de tener permisos de edición directos en el repositorio fuente. 
Es la base del desarrollo colaborativo externo, ya que permite modificar el código de manera autónoma antes de proponer mejoras.
